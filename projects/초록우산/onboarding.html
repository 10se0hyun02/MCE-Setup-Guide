1프로젝트 개요

고객사초록우산 어린이재단
솔루션Salesforce Marketing Cloud Engagement (MCE)
수행사밀버스
운영 시작2026년 9월 18일
담당 역할MCE 운영 (이메일 발송·자동화·데이터 관리·성과 보고)

초록우산 어린이재단이 기부자·후원자에게 이메일을 발송하고, 기부 여정을 자동화하기 위해 Salesforce MCE를 도입한 프로젝트입니다. 구축 완료 이후 밀버스가 상시 운영을 담당하고 있습니다.

2MCE(Marketing Cloud Engagement)란?

Salesforce가 제공하는 기업용 이메일 마케팅 + 마케팅 자동화 플랫폼입니다.

일반 이메일 서비스(Gmail 등)와 달리 MCE는 다음을 지원합니다.

  • 대량 발송: 수십만 명에게 개인화된 이메일을 동시 발송
  • 전달률 관리: 전용 IP + 인증 도메인으로 스팸 분류 방지
  • 자동 여정(Journey): "기부 완료 → 3일 후 감사 메일 → 30일 후 리마인드" 같은 흐름 자동화
  • 성과 측정: 오픈율·클릭율·이탈율 실시간 리포트
💡
초록우산 운영에서는 주로 이메일 발송 관리, Journey(자동 여정) 모니터링, 데이터 동기화 확인, 성과 보고가 핵심 업무입니다.

3주요 앱 — 운영에서 자주 쓰는 것

MCE는 용도별로 여러 앱으로 구성되어 있습니다. 운영 중 실제로 접하게 되는 앱 위주로 정리합니다.

✉️Email Studio
이메일 발송, 구독자 관리, 수신거부 처리, 발송 성과 확인
발송 직전·직후, 이슈 처리 시
🖼️Content Builder
이메일 템플릿·이미지·HTML 블록 제작 및 라이브러리 관리
발송물 제작·수정 시
🗺️Journey Builder
고객 행동 기반 자동 이메일 여정 설계·운영
자동화 캠페인 모니터링·수정 시
⚙️Automation Studio
SQL 쿼리로 세그먼트 생성, FTP 데이터 가져오기, 정기 배치 자동화
데이터 동기화·정기 처리 시
🌐CloudPages
수신거부 페이지·구독 페이지·랜딩 페이지 운영
수신거부 처리, 캠페인 랜딩 시
📊Analytics Builder
발송 성과 리포트 및 대시보드
주간·월간 보고 시

4핵심 용어

처음 접하면 낯선 약어들입니다. 회의나 문서 이해를 위해 먼저 읽어두세요.

용어 설명
BUBusiness Unit MCE의 독립 운영 단위. Parent BU(관리용)와 Child BU(실제 발송)로 나뉨. 브랜드·목적별로 분리
DEData Extension 구독자·발송 데이터를 담는 테이블. DB 테이블과 동일한 개념. MCE에서 List 대신 DE를 씀
SAPSender Authentication Package 전용 발신 도메인 + 전용 IP + DKIM 인증을 묶은 패키지. 이메일 도달률에 직결됨
IP Warming 신규 전용 IP의 발신 신뢰도를 쌓기 위해 소량(200건)부터 점진적으로 발송량을 늘리는 과정. ISP 스팸 분류 방지
Send Classification Commercial(마케팅·뉴스레터)과 Transactional(주문확인·OTP)의 법적 구분. Transactional은 수신거부자에게도 발송 가능
AMPscript MCE 전용 스크립팅 언어. 이메일 본문 내 이름·기부금액 등 개인화에 사용
FTPEnhanced FTP 고객사 DB → MCE로 구독자 파일을 올리는 파일 서버. Automation Studio와 연동해 자동 동기화
Bounce 이메일 발송 실패. Hard Bounce(영구 오류, 주소 없음)와 Soft Bounce(일시 오류, 수신함 가득 참) 구분
SPF / DKIM / DMARC 이메일 인증 DNS 레코드. SPF: 허가된 발송 서버 등록. DKIM: 위변조 방지 서명. DMARC: 인증 실패 시 정책
AS / JB Automation Studio / Journey Builder 약칭

5운영 담당자의 주요 업무

상시 모니터링
  • 캠페인·Journey 발송 성과 확인 (오픈율·클릭율·이탈율·스팸 신고)
  • Automation Studio 스케줄 오류 점검
  • Journey Builder 흐름 이상 점검
  • DE 데이터 동기화 상태 확인
캠페인 지원
  • 고객사 요청 이메일 발송 (단발성 캠페인 실행)
  • Content Builder에서 템플릿 수정·신규 제작
  • 발송 전 테스트 발송 및 렌더링 검수 (주요 클라이언트 기준)
이슈 대응
  • 발송 실패·Bounce 급증 원인 파악 및 처리
  • 수신거부 요청 접수 및 반영 확인
  • IP 평판 모니터링
  • 고객사 문의 대응 및 에러 리포트 작성
보고
  • 주간/월간 발송 성과 보고서 작성
  • 고객사 보고 자료 준비 (Analytics Builder 데이터 기반)

6업무 아카이브 구조

폴더 구조

업무 이력과 산출물은 아래 경로에 쌓입니다.

📁 projects/초록우산/ 프로젝트 루트 폴더
📄 project.md 프로젝트 메타 정보 (고객사·솔루션·기간·담당자)
📝 history.md 날짜별 업무 로그. 최신 항목이 위에 위치
📁 meetings/ 회의록 (YYYY-MM-DD-제목.md 형식)
📁 docs/ 고객사로부터 받은 자료·산출물
📁 reports/ 주간 보고서

업무 대시보드

dashboard.html을 브라우저에서 열어 사용합니다. 할일·이슈·커뮤니케이션·회의록을 탭별로 관리합니다.

📅 할일 Daily/Weekly 업무 목록. 미완료 항목 이월 관리
💬 커뮤니케이션 고객사·내부 커뮤니케이션 이력 (카드·타임라인 뷰)
⚠️ 이슈 발생한 이슈·트러블슈팅 이력. 우선순위·상태 관리
🎙️ 회의록 회의 내용 기록. 좌측 목록 + 우측 에디터

7인수인계 체크리스트

신규 담당자가 업무를 시작하기 전에 확인해야 할 항목입니다.

접근 권한 확인
  • MCE 계정 발급 및 접근 가능한 BU 확인
  • Enhanced FTP 접근 정보 확인
  • Salesforce Support 포털 접근 권한
운영 현황 파악
  • 현재 활성화된 Journey 목록 및 트리거 조건 확인
  • Automation Studio 스케줄 목록 및 주기 확인
  • DE 목록 및 데이터 동기화 방식 파악
  • IP 평판 상태 확인
  • 수신거부 처리 프로세스 파악
고객사 커뮤니케이션
  • 고객사 담당자 연락처 확인
  • 정기 보고 일정·형식 파악
  • 긴급 이슈 에스컬레이션 경로 확인
업무 이력 파악
  • history.md 최근 항목 읽기
  • 대시보드 이슈 탭에서 열린 이슈 확인
  • 대시보드 커뮤니케이션 탭에서 최근 내용 확인
📌
인수인계 첫 날에는 전임 담당자와 함께 MCE 화면을 직접 보면서 활성 Journey 흐름과 Automation 스케줄을 확인하는 것을 권장합니다.
