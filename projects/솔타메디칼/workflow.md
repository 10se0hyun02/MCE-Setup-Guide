## 작업별 처리 방식

1. 시나리오 중심 질문지 작성 (마케팅 대상·원하는 시나리오·혜택·필요 데이터 유무)

- 파일: `meetings/YYYY-MM-DD-제목.md`

### 보고서 작성 및 검토 기준
> 2026-10-16 사용자 요청으로 반영. 현업 인터뷰 결과보고 초안(V1.0_261015)과 이사님 수정본(20261015)을 비교해 관찰한 방향을 다음 보고서의 참고 기준으로 사용한다. 이사님의 모든 보고서에 적용되는 고정 원칙이나 개별 수정의 의도로 단정하지 않는다.

1. **설계, 결정에 영향을 주는 정보를 우선한다.** 인터뷰 내용을 빠짐없이 나열하기보다 시나리오, 데이터, 콘텐츠, 일정 결정에 필요한 내용을 본문에 담는다. 중요한 세부사항은 관련 과제와 연결하고, 본문에서 덜어낸 상세 내용은 원문이나 별첨에서 추적할 수 있게 한다. 삭제된 내용을 사실 오류로 간주하지 않는다.
2. **현황 → 니즈 → 과제가 직접 연결되게 쓴다.** 현황이 어떤 업무상 필요를 만들며, 이를 위해 무엇을 설계하거나 확인해야 하는지 보여준다. 예: 고객 식별 정보가 연결되지 않음 → 고객별 타겟팅, 반응 이력 관리 필요 → 고객 매칭 기준과 연동 방식 확인.
3. **대상과 관계를 구체적으로 쓴다.** 무엇과 무엇을 연결하는지, 누가 무엇을 관리하는지 명시한다. ‘연계 필요’, ‘관리 개선’, ‘자동화 검토’에는 대상과 조건을 붙인다. 원문에 없는 범위, 수량, 확정 표현을 임의로 추가하지 않는다.
4. **범위와 책임을 구분한다.** 포함, 제외, 미확정 상태와 결정 주체, 협의 주체, 실행 주체를 확인한다. 수정본의 문구나 색상 변경만으로 실제 업무 범위, 책임이 확정됐다고 기록하지 않는다. 도식의 박스, 연결선, 색상, 점선, 범례는 본문의 상태와 일치시킨다.
5. **핵심 문장을 선택해 강조한다.** 페이지별 주요 니즈, 우선순위, 선행 조건, 설계 과제, 결정할 사항이 드러나게 한다. 강조색을 수정 이력 표시와 혼용하지 않으며, 모든 문장을 강조하지 않는다.
6. **순서와 나열을 구분하고 표기를 통일한다.** 고객 여정, 업무 단계처럼 순서가 있는 내용은 화살표 등으로 흐름을 표현하고, 병렬 항목은 쉼표나 접속어로 읽기 쉽게 정리한다. 호칭, 날짜, 용어, 쉼표 뒤 공백, 페이지 번호를 통일한다. 수정본에 남은 표기 불일치를 그대로 답습하지 않는다.

7. **내부 리뷰 전달 전에 문장 검수를 완료한다.** 이사님이 직접 지적한 ‘문장이 어색하거나 이해가 잘 안되는 부분의 사전 검수’를 반영한다. 맞춤법뿐 아니라 문장의 자연스러움과 의미 전달을 별도로 점검한다. 인터뷰에 참석하지 않은 독자도 추가 설명 없이 이해할 수 있는지 읽어보고, 주어, 서술어 호응, 생략된 대상, 모호한 수식어, 지나친 명사 나열과 압축 표현을 정리한다. 긴 문장은 의미 단위로 나누되 사실, 수치, 조건은 보존한다. 뜻이 불분명하면 원문이나 담당자에게 확인하고 추측으로 매끄럽게 고치지 않는다.

8. **AI 특유의 말투와 불필요한 장식을 제거한다.** 다음 항목을 전달 전에 모두 점검하고, 해당 표현이 있으면 삭제하거나 자연스러운 업무 문장으로 고친다. 특정 표현이 있다는 이유만으로 AI 작성 여부를 판단하지 않는다.

| 점검 대상 | 작성 기준 |
|---|---|
| 가운데점과 대시 | 제목과 본문의 나열용 가운데점, 부연 설명용 긴 대시, 장식용 하이픈을 사용하지 않는다. 쉼표, 접속어 또는 별도 문장으로 바꾼다. |
| 기호와 장식 | 문장 대신 화살표, 슬래시, 세로줄을 연달아 쓰지 않는다. 장식용 이모지, 반복되는 콜론형 제목, 불필요한 따옴표와 괄호를 없앤다. 실제 순서를 보여주는 도식의 화살표는 필요한 경우 사용한다. |
| 번역투와 피동 | ‘~에 있어서’, ‘~를 통해’, ‘~에 기반하여’, ‘~에 의해’, ‘~되어지다’ 같은 표현의 반복을 줄인다. 주체와 행동을 직접 쓰고 이중 피동을 고친다. |
| 추상어와 명사 나열 | ‘고도화’, ‘최적화’, ‘효율성 제고’, ‘가치 창출’, ‘시너지’만으로 내용을 대신하지 않는다. 무엇을 어떻게 바꿀지 쓰고, 근거 없는 수식어는 삭제한다. |
| 상투적인 도입과 결론 | ‘주목할 만하다’, ‘시사하는 바가 크다’, ‘핵심은 ~에 있다’ 같은 내용 없는 평가와 ‘결론적으로’, ‘요약하면’ 뒤에 같은 내용을 반복하는 문장을 없앤다. |
| 접속사와 설명 반복 | ‘또한’, ‘아울러’, ‘나아가’, ‘따라서’, ‘즉’을 습관적으로 붙이지 않는다. ‘이는 ~라는 의미다’처럼 앞 문장을 되풀이하는 설명을 줄인다. |
| 기계적인 문장 구조 | ‘단순히 A가 아니라 B’, ‘A를 넘어 B로’, ‘A에서 B로’ 같은 대조나 전환 공식을 반복하지 않는다. 항목을 억지로 세 개씩 맞추거나 문장 길이와 종결을 획일적으로 만들지 않는다. |
| 영어와 과도한 격식 | 불필요한 영어 병기와 외래어를 줄이고 익숙한 한국어를 쓴다. 제품명과 필요한 업계 용어는 유지하며, 보고서의 격식은 지킨다. |
| 과장과 단정 | ‘획기적’, ‘압도적’, ‘혁신적’ 등 근거 없는 홍보 표현을 삭제한다. 문장을 간결하게 만들려고 ‘가능’, ‘예정’, ‘추정’, ‘확인 필요’를 없애거나 확정 표현으로 바꾸지 않는다. |
| 과도한 서식 | 굵은 글씨, 소제목, 불릿을 모든 문장에 적용하지 않는다. 비교는 표로, 순서는 번호로, 설명은 문장으로 쓰되 필요한 구조만 남긴다. |

날짜, 파일 경로, URL, 공식 명칭, 직접 인용, 수식과 범위 표기 안의 기호는 보존한다. 마크다운 목록과 표에 필요한 하이픈도 유지한다. 문체를 고칠 때 사실, 수치, 조건, 인과관계, 불확실성의 수준을 바꾸지 않는다.

> 근거 구분: 1~6번은 수정본 비교에서 도출한 참고 기준이며, 7번의 사전 검수 필요성은 사용자가 전달한 이사님의 명시적 피드백이다. 세부 점검 방법은 이를 실행하기 위한 작성 기준이다. 8번은 AI 특유의 문체와 기호 사용을 없애 달라는 사용자의 요청을 반영했다.
